# ADR-005: Canonical patient identity

**Status:** Accepted (Stage 0; CLAUDE.md §7, spec §6.1)

## Context
Duplicated patient records across OPD, IPD, pharmacy, billing and nursing fragment the clinical history and cause billing and safety errors.

## Decision
A single `Patient` entity per person per tenant, referenced by every module. Identifiers live in a separate `PatientIdentifier` table (type, value, issuer, tenantId; unique `(tenantId, type, value)`): MRN, legacy hospital ID, external ID, ABHA later. The MRN is generated by the numbering engine. Patients are never hard-deleted; status flags (`ACTIVE`/`INACTIVE`) apply. Possible duplicates are detected (mobile, name+DOB, name+age) and shown, **never auto-merged**; a deliberate "create new anyway" is an audited override. A future merge would be a separate, audited, reversible workflow (backlog).

## Alternatives considered
- **Per-module patient records:** rejected, fragments history.
- **Identifier columns on `Patient`:** rejected, does not scale to ABHA/legacy IDs.
- **Automatic merging:** rejected for patient-safety reasons (wrongly merged charts).

## Consequences
+ One longitudinal history; all clinical/financial records reference `patientId`.
− Duplicate detection is probabilistic; staff judgement is part of the workflow.
− Mobile numbers are shared within families, so mobile is a search key, not a uniqueness key.
